# Codi upstream sync

`.github/workflows/upstream-sync.yml` merges `pingdotgg/t3code` main (upstream, "Codi")
into this fork (Codi) every night. Read its header comment first: it describes the steps and
the secrets. This skill holds what that file does not: how to find out why a run failed, the
failures seen so far, and how to do the merge by hand.

## Conflict policy

[codi-upstream-merge](../codi-upstream-merge/SKILL.md) holds the maintainer's policy and the
fix patterns. The workflow passes that file to its Claude step as the prompt, so edit the policy
there, not in the workflow. In short: upstream wins; the fork keeps Telescope, i18n `t()` calls
and a few named assets; a change to Telescope's design goes to a pull request.

## Diagnose a failed run

1. List runs: `mcp__github__actions_list` with `resource_id: upstream-sync.yml`. A scheduled run
   starts about 7 hours after its 02:00 UTC cron; a run that has not appeared yet has not failed.
2. Read the failed job with `mcp__github__get_job_logs` (`failed_only`, `return_content`). The
   tool returns at most 5000 lines, and the run-log zip host is blocked from cloud sessions. A
   long `check:changed` pushes typecheck errors out of the tail. Then reproduce instead:

   ```bash
   git fetch upstream main
   U=$(git rev-list -1 --before="<run start, UTC>" upstream/main)
   git rev-list --count <run head sha>..$U   # must equal "Upstream is N commits ahead"
   git checkout -B probe <run head sha> && git merge --no-edit $U
   ```

3. Find the step that failed: the merge, Claude's conflict step, or `check:changed`. Match the
   error against the table below before reading code.

## Catch up by hand

Use this when main is far behind or the nightly run keeps failing on the same thing.

1. Start from current main on a local branch, and merge with the bot identity the workflow uses:

   ```bash
   git fetch origin main && git fetch upstream main
   git checkout -B sync-work origin/main
   git config user.name "github-actions[bot]"
   git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
   git merge --no-edit upstream/main
   git checkout --theirs apps/server/src/provider/agentContextBudget.json
   git add apps/server/src/provider/agentContextBudget.json
   node scripts/resolve-rebrand-conflicts.mjs   # resolves rename-only conflicts
   ```

2. Resolve the rest by the policy. Sort them first: for each conflicted file, compare the fork's
   side with `Codi` turned back into `Codi` against the merge base. A fork side that differs
   only by the rename takes upstream's side. For i18n files, take upstream's JSX and put back the
   fork's `t()` calls where the key exists; leave text upstream added as English.
3. `pnpm-lock.yaml`: resolve `package.json` files first, then
   `git checkout --theirs pnpm-lock.yaml && vp install --no-frozen-lockfile`.
4. Commit and re-apply the rename:

   ```bash
   git commit --no-edit --no-verify
   node scripts/rebrand-codi.mjs
   node scripts/refresh-agent-context-budget.ts
   git diff --name-only | xargs -r vp fmt --no-error-on-unmatched-pattern
   git commit -qam "chore: re-apply the Codi rename after the upstream merge" --no-verify
   ```

5. Check: `vp run typecheck`, then `vp run check:changed upstream/main`. Fix what the merge broke
   in a separate commit.
6. Before pushing, fetch `origin main` again. If it moved, redo the merge on the new main and
   reuse your resolutions with `git checkout <old merge commit> -- <conflicted files>`. Then
   `git diff <old tip> HEAD` must show only the new main commits.
7. Push to main with `git push origin HEAD:main`, then `git config --unset user.name` and
   `git config --unset user.email`.

## Cloud container traps

These cause failures that are not in the code. Check CI's result for the same tests before you
chase them.

- The container has Node 22, the repo wants Node 26: `DisposableStack is not defined` and
  `Invalid regular expression ... (?i:` come from that. So do tests that need Electron's
  download, `ssh-keygen`, `tailscale` or partial-clone git.
- `vp` is not installed, and `curl ... | bash` is blocked. Install the pinned version from npm
  (`npm i -g vite-plus@<version in pnpm-workspace.yaml>`). Then put the repo's own
  `node_modules/.bin` first in `PATH`; the global `vp` loads its own vitest, and tests fail with
  "Vitest failed to find the current suite".
- `cdn.playwright.dev` is blocked. For a local run only, link the preinstalled browser to the
  revision Playwright wants, and remove the link afterwards:

  ```bash
  ln -sfn /opt/pw-browsers/chromium_headless_shell-<installed> \
    ~/.cache/ms-playwright/chromium_headless_shell-<wanted>
  ```

- `check:changed` kills the test step after 900s on 4 cores. Set `CHECK_CHANGED_TIMEOUT=3000`.
- The session's GitHub app may not have Actions write, so `run_workflow` returns 403. Ask the
  maintainer to press Run workflow, and say a re-run checks out the latest main again.

## Landing

- Checks pass and Telescope's design is untouched: the workflow pushes to main.
- Otherwise it pushes the `upstream-sync` branch and opens or updates a pull request, and the
  next run continues from that branch. Merge that pull request with **Create a merge commit**,
  never squash: a squash drops upstream's commits from main's history, and the next merge
  conflicts on all of them again.
- `UPSTREAM_SYNC_TOKEN` needs Contents, Workflows and Pull requests (read and write). Without
  Pull requests the workflow falls back to `GITHUB_TOKEN`, and that pull request starts no CI.
